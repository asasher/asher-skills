# To-spec probes

Pre-deployment probes with `SKILL.md`, `reference/synthesis.md`, and `reference/template-guide.md` in context. Require an exact citation for each answer.

## Scenario

A design conversation settled a driver-payout direction. Retry policy was discussed but never decided. Research and prototype projections are present in the shaping record.

## Probes

**P1.** Do you ask about retry policy?

**P2.** How must every Notes line be classified, and what does a blocking Note mean?

**P3.** The conversation named a source file and a prototype-validated reducer. Which may appear in the spec?

**P4.** Where does the completed spec go, and does `to-spec` publish it or change the ticket?

**P5.** What opens the spec body?

**P6.** The direction needs three builds. Do you create tickets?

**P7.** What does the spec carry for the research dossier and prototype?

**P8.** What must the fidelity audit prove?

## Answer key

- **P1:** No. Undecided points "become Notes lines, never questions."
- **P2:** Blocking, delegated, or deferred. "An open blocking Note means the direction is not ready to build on."
- **P3:** Only the prototype-validated fragment. The spec carries no file paths or code snippets except that fragment and Supporting-artifact pointers.
- **P4:** Write "an untracked scratch file" and return its path. The description says "no interview or publication"; no tracker mutation belongs to this skill.
- **P5:** "Every spec opens with a diagram of the moving parts."
- **P6:** No. End with a recommended split, "not created tickets."
- **P7:** One Supporting artifacts entry per decision-informing artifact with its kind, question, one-line takeaway, and durable pointer.
- **P8:** Every material source decision appears in the spec, every Notes line is classified, and every spec statement traces to the source material.

Pass bar: eight of eight on both executors.
