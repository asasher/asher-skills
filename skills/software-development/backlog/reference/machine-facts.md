# Machine facts — classification and homes

A machine fact written into a tracked playbook travels with the repo — to clones, cloud runners, and
machines it is false on. A recorded probe *result* is stale on arrival, and the same fact restated in
two files will eventually disagree. So: classify every machine fact a setup or session records, then
give it the one home its class prescribes.

## Three classes

1. **Verify-at-use** — the default. Anything a cheap live probe re-derives: tool presence, flag
   acceptance, auth liveness, a route answering at all. The playbook records the *probe command* — one
   that exercises the capability itself (`gh auth status`, a bounded executor echo), never a version
   string standing proxy for it — and never the probe's result. Harness and CLI versions are never
   recorded as ground truth or as an expectation: a version literal appears only as dated metadata
   inside a stamped probe record (class 3), never as a value a session resolves against. A runtime
   requirement the code itself imposes ("Python 3.10+") is a project fact, not a machine fact — state
   the requirement, not the observation.
2. **Machine-local** — real facts no cheap command re-derives: auth identity, local ports, device
   names, local absolute paths outside the repo. These live in the gitignored overlay (below),
   regenerated by the owning skill's setup; the tracked playbook carries a pointer, never the fact.
3. **Expensive probe caches** — results costly to re-derive, model and capability reachability first
   among them: is this route invocable, effect-verified, on this machine. Cross-harness effect probes,
   sandbox-behavior verdicts, alias-acceptance rules. These stay tracked — re-probing per run would be
   worse — but always under a machine-record stamp (below), so the guard is mechanical, not prose.
   A CLI version observed while probing rides the record as incidental metadata — it cues the
   re-probe after an upgrade — never as a recorded fact of its own.

## One fact, one home

Each machine fact has exactly one authoritative location; every other document points at it or records
the probe command. Model and capability reachability — routes, dispatch aliases, effect-probe
verdicts — lives only in the staffing playbook's probe record (`docs/agents/staffing.md`), the CLI
versions its probes observed riding along as that record's metadata; an environment or platform
playbook restating a route, an alias, or a version is drift.

## The stamp marker

A tracked file or section carrying expensive probe results opens with this HTML comment on its own
line — machine-readable, parsed by the checker:

    <!-- machine-record: machine=<hostname> probed=<YYYY-MM-DD> -->

The machine value is the machine's stable short name: the hostname before its first dot — on macOS
the local host name (`scutil --get LocalHostName`), which survives transient network renames — and
the comparison is case-insensitive. The date follows the
establishing-observation rule: it dates the run that established the recorded state; a re-run that
confirms everything rewrites nothing.

## The machine-local overlay

`docs/agents/local/` — gitignored (setup ensures the `.gitignore` entry) — holds one file per tracked
playbook it extends, same basename: `docs/agents/local/environment.md` extends
`docs/agents/environment.md`. Each overlay is regenerated by the owning setup, never committed, and
opens with its own machine-record stamp. The tracked playbook declares each overlay with a pointer
marker on its own line:

    <!-- machine-local: docs/agents/local/<name>.md setup="<skill> setup" -->

plus one prose sentence naming what lives there and the setup to run when the file is missing.

## The checker

This skill ships `scripts/check-machine-facts.py`: it walks every `*.md` under `docs/agents/` for both
markers — a machine-record naming another machine is stale, a declared overlay whose file is absent is
missing, a marker that matches the prefix but not the grammar is malformed. The question it asks is
whether each record still belongs to this machine — never whether version numbers match: versions are
metadata, and capability trust is re-established by the owning setup's probes, not by string
comparison. Findings print one per line on stdout; a nonzero exit means at least one. `backlog
build`'s preflight runs it, and any setup runs it as its last step, resolving what it names.
