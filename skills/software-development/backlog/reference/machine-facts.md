# Machine facts — one rule, two classes

A machine fact written into a tracked file travels with the repo — to clones, cloud runners, and
machines it is false on. A recorded probe *result* is stale on arrival, and no stamp or caveat fixes
that: on every machine but the probing one, the record's only correct reading is "ignore this". So the
rule is absolute: **a tracked file never records a machine fact.** Classify what a setup or session
learns about the machine, then give it the one home its class prescribes.

## Two classes

1. **Verify-at-use** — the default. Anything a cheap live probe re-derives: tool presence, flag
   acceptance, auth liveness, a route answering at all. The playbook records the *probe command* — one
   that exercises the capability itself (`gh auth status`, a bounded executor echo), never a version
   string standing proxy for it — and never the probe's result. A runtime requirement the code itself
   imposes ("Python 3.10+") is a different thing entirely — a project fact, not a machine fact, stated
   as the requirement, never as the observed version.
2. **Machine-recorded** — everything a session must read rather than re-derive, whether it is cheap to
   name (auth identity, local ports, device names, local absolute paths outside the repo) or expensive
   to probe (route reachability, effect verdicts, alias acceptance, sandbox behavior). All of it lives
   in the gitignored overlay (below), regenerated by the owning skill's setup; the tracked playbook
   carries a pointer and the probe command, never the fact. Expense changes how often the owning setup
   re-probes — it never changes the home. A CLI version observed while probing rides the overlay's
   record as incidental metadata — the cue to re-probe after an upgrade — never as a value a session
   resolves against.

## One fact, one home

Each machine fact has exactly one authoritative location; every other document points at it or records
the probe command. Model and capability reachability — routes, dispatch aliases, effect-probe
verdicts — lives only in the staffing overlay (`docs/agents/local/staffing.md`, declared by the
tracked staffing playbook), the CLI versions its probes observed riding along as that record's
metadata; an environment or platform playbook restating a route, an alias, or a version is drift.
That home is for dispatch reachability: a verdict about a repo's own verification surface — a browser
launching headless, a sandbox refusing a command shape — lives in the overlay of the playbook that
owns the surface.

## The machine-local overlay

`docs/agents/local/` — gitignored (setup ensures the `.gitignore` entry) — holds one file per tracked
playbook it extends, same basename: `docs/agents/local/environment.md` extends
`docs/agents/environment.md`. Each overlay is regenerated by the owning setup, never committed, and
opens with a machine-record stamp on its own first content line — machine-readable, parsed by the
checker:

    <!-- machine-record: machine=<short hostname> probed=<YYYY-MM-DD> -->

The stamp guards the one way an overlay can still lie: a file copied from another machine, or a
hostname rename. The machine value is the machine's stable short name: the hostname before its first
dot — on macOS the local host name (`scutil --get LocalHostName`), which survives transient network
renames — and the comparison is case-insensitive. The date follows the establishing-observation rule:
it dates the run that established the recorded state; a re-run that confirms everything rewrites
nothing.

The tracked playbook declares each overlay with a pointer marker on its own line:

    <!-- machine-local: docs/agents/local/<name>.md setup="<skill> setup" -->

plus one prose sentence naming what lives there and the setup to run when the file is missing.

## The checker

This skill ships `scripts/check-machine-facts.py`: it walks every `*.md` under `docs/agents/` and
enforces the rule mechanically. A machine-record stamp in a tracked file is a finding — machine facts
belong in the overlay, whatever prose surrounds them. A declared overlay whose file is absent is
missing. An overlay that does not open with a stamp, or whose stamp names another machine, is
untrusted. A marker that matches the comment prefix but not the grammar is malformed. Findings print
one per line on stdout; a nonzero exit means at least one, and the remedy is always the same: re-run
the setup that owns the named record, on this machine. `backlog build`'s preflight runs the checker,
and `backlog setup` ends with it. On a fresh clone every declared overlay is absent by construction —
those findings are the expected first-run state naming the setups to run, not a fault.
