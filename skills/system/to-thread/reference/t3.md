# Route: T3 Code

Resolve provider availability, model, effort, and authorized runtime mode from the running app's schema.

## Dispatch

Run the bundled helper with the prepared directory:

    scripts/t3-thread.py --name "<name>" --prompt "<prompt>" \
      --project-directory <project-root> --directory <directory> --branch <branch> \
      --provider <instance-id> --model <model> --effort <effort> \
      --runtime-mode <mode>

The project root must be registered in T3; the directory is the prepared working directory, a secondary worktree for shaping or building. Use a recognized provider instance ID. On Linux, pass `--t3-executable` and `--server-entry` explicitly; automatic discovery targets the macOS bundle. The helper supports loopback servers in the standard T3 home.

## Verify the launch

Confirm the named thread is attendable and its turn started successfully. Check the configured model and effort against the request.

Compatibility traps observed in T3 Code (Alpha) 0.0.33 on 2026-08-24:

- An unknown provider ID can fail asynchronously after a successful helper exit.
- claudeAgent can report a rejected model as a completed turn. Read the first assistant message for provider errors; `~/.t3/userdata/logs/provider/events.<threadId>.log` carries it and the session configuration.
- Effort option IDs differ: claudeAgent uses `effort`, codex uses `reasoningEffort`. The helper maps known instance names; use `--effort-option-id` for another name. Unsupported effort may be rejected or silently coerced, so verify the configured value.

## Failure and handoff

Read stdout JSON even on a nonzero exit: it preserves any known thread ID, branch, directory, and turn state. `turn_state: unknown` means the start may have succeeded; retain ownership and the worktree, then inspect that thread before retrying or deleting it. The helper only deletes after a definite start rejection or before sending a start.

`session_revocation: failed` reports authentication cleanup separately from dispatch. A `start_acknowledged` thread still needs the launch verification above; do not create another worker because revocation failed. Auth commands and HTTP requests have 30-second timeouts. Report schema, authentication, project, or runtime incompatibility with the preserved identity and recovery state.

Return the verified thread ID/name, branch, and directory. Tell the user to open the named thread in the T3 project sidebar.
