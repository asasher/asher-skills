Treat notifications as alarms.

1. Interrupt only when timely user action is required. If the required action is unnamed, route to a quiet surface.
2. Rationalize each notification class before shipping: action, urgency window, consequence if missed, sender, destination, quiet fallback, rate limit, expiry or batching, and suppression.
3. Put status updates, reports, recommendations, marketing, and other FYI signals in activity feeds, logs, status panels, inboxes, or scheduled digests.
4. Give human messages, urgent actions, and FYI surfaces distinct visual treatments; differentiate sounds where used.
5. Prevent floods and standing alarms: rate-limit senders, collapse repeated events, expire stale items, and tie persistent badge counts to an obvious response.
6. Preserve credibility: remove, downgrade, or batch false positives, nuisance signals, stale badges, and ignored notifications; reduce interrupt rights for senders with low read or action rates.
7. Make scheduled summaries or user-chosen delivery windows the primary controls for low-urgency delivery.
8. Reserve urgent notification signals for the receiver’s time-sensitive needs.
