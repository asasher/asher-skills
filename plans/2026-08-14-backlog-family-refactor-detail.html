Theses

Pull, not push. No living supervisor. Outcomes land in the tracker; anyone reads them there. "Resume" means "run it again."
Bars, then cheapest. State the quality a task needs, then take the cheapest model that clears it. Never maximize quality and glance at cost.
Runtime checks, not recorded state. Try the route. On failure: warn, fall back. No probe ledgers, no overlays, no self-heal state machines.
Merge up, slice down. Groom absorbs fragments into one shapeable subject; to-slices cuts the blessed spec into buildable slices.
Branches hold artifacts. Specs, prototypes, dossiers iterate on branches; tickets carry a projection and a commit hash. Main stays clean.
Plain words, no bare numbers. User-facing text follows ASD-STE100, uses the CONTEXT.md dictionary, and every ticket/PR number carries a description.
Main carries only what must stay true. Anything with a shelf life — specs, prototypes, dossiers, one-work verification scripts — lives in the tracker or on artifact branches, where expiry is deleting a ref, not a cleanup chore.

The shape, before and after

Workstream 1Backlog: groom

Merge step settled new

Before any thread exists, groom proposes ticket merges: many small related tickets are absorbed into one shapeable subject. Default is absorption — one ticket carries the merged body; the others close as duplicates pointing at it. The capstone-style parent is reserved for the split that comes after shaping. Merging fragments is safe because slicing exists: the spec re-creates structure on the way out, informed by settled decisions.

The batch construct deleted

Batches and subjects were runtime groupings whose value evaporated when the thread ended. Their three jobs go to durable mechanisms: duplicates → merge/close; interlocked decisions → merge, then split post-spec; merely-related → concurrent shaping threads reconcile, which shape already handles. Batch-atomic readiness goes with it: readiness becomes per-subject, bound to a blessed spec hash (WS5).

Attention-aware width settled

Shaping requires the user's active attention, so groom asks how many threads to start (default 3). The unstarted remainder stays routed in the tracker for the next groom or a "start two more." Width belongs to the bounded resource: build's bounded resource was money (fixed by staffing), shaping's is attention (cannot be fixed).

Kept as-is

The chat-readable plan discipline (id + title + digest, relations in words), the confirmation gate before any tracker write, and the teardown sweep — which generalizes into backlog status (WS2).

Workstream 2Backlog: build & status

Before — supervised

  • Session babysits the fleet; completions wake it
  • Concurrency cap + queue semantics
  • Quota gate + usage surfaces + outcome accounting
  • serialize-verification + lane lock + stale takeover
  • Rollback / resume-reconcile / deadline recovery prose
  • Builds dispatched as supervised subagents

After — pull

  • One thread per ticket via to-thread; dispatcher exits
  • No cap, no queue — groom's readiness gate is the budget
  • No quota gate — staffing repair removes the cause (#195 closes)
  • Repo is parallel-safe or build does not dispatch (WS6)
  • Re-run backlog build; idempotent — skips live claims
  • Dispatch declaration + per-build deadline, stated up front

Dispatch declaration = the claim settled new

A statement, never a question: "Dispatching #142 — rename capstone to spec — model sonnet-5, effort high, harness Claude Code, deadline 18:30Z." The human can interrupt; nobody must approve. The declaration and the tracker claim are one event with two audiences: the same content is posted as the claim comment — ticket digest, branch, worktree path, model, effort, harness, thread name, dispatcher identity, and the deadline as an absolute timestamp (any machine must be able to rule on it). In the pull model the deadline has nowhere else to live: the supervisor that held it in memory is deleted, and a status query can only report "stalled" from durable state. Lives in the dispatch contracts (to-subagent, to-thread) so every caller gets it.

backlog status new

A pure query replacing the babysitting loop: tracker claims × live worktrees × change-request state × the deadlines read from the claims. Reports finished, stalled-past-deadline, and orphaned work. Groom's teardown sweep becomes this verb's action arm.

Abandonment is derived, never written settled

No abandoned label. building + deadline passed + thread not observably alive (dead thread listing, no branch activity) is abandoned — derived at read time by status. Pickup follows sharpened existing rules: audit reality first (a slow build may still be running — liveness decides, not the clock alone); adopt committed work (a reclaim resumes from the branch, never from scratch, so nothing is discarded); another actor's expired claim is the existing lane-takeover-note pattern. The reclaim is a new claim comment superseding the old — the ledger stays event-shaped: claim, outcome, reclaim. The multi-day quiet horizon survives only as backstop for claims that predate deadlines. Guardrail: the tracker records transitions, not telemetry — no heartbeats, no progress comments; liveness is checked at read time.

What survives

The per-build deadline (the real runaway protection — the cap never was), abort-path teardown (owned by the thread that owns the worktree), the orphan sweep's quiet horizon, and the label roles.

capstone → spec settled

The work-type renames to the word the system already uses. Guard sentence in the policy: every shaped ticket has a spec; only a split parent has the spec work-type — the label names dispatch behavior (coverage check over children), not artifact presence. Role→label mapping keeps existing consumer repos compatible.

Workstream 3Staffing

The defect settled

Resolution ranks intelligence > taste > cost descending. Fable-5 tops both axes, so it wins every ranking and cost never breaks a tie — everything defaults to Fable. The succession lists repeat the pattern (orchestrator: fable → opus → sonnet).

Before — maximize, then glance at cost

  • Rank survivors by intelligence desc, taste desc, cost last
  • "Routine never means cheapest-first"
  • Machine overlay: probe records, reachability rows, effect classes
  • Self-heal state machine, retry-at tokens, evidence fields
  • Pre-dispatch preflights (check-machine-facts.py, effect probes)

After — bars, then cheapest

  • Caller states the intelligence bar and taste bar the task needs
  • Filter models below the bars; take the cheapest survivor
  • Coordination class = the coarse form of the bars
  • Runtime checks only: try the route; on failure warn + fall back
  • Overlay, probes, self-heal, machine-audit: deleted
  • Playbook shrinks to: roster table + pins + repo deltas

"Escalate without asking when cheaper output misses the bar" is already in the doctrine — it becomes the center of the design instead of a footnote. Kept: the pins (mechanical → gpt-5.6-sol), the taste gate (now one bar among the bars), and the reliable command shapes for cross-harness dispatch (knowledge earned in #173 — text, not probe state). A route that fails repeatedly across sessions is retro fodder, not a state machine's job.

Dissolves with the overlay: #196 (overlays never materialise in worktrees), #205 (one-directional drift rule), most of #199 (preflight halts prescribing unrunnable remedies).

Workstream 4Dispatch spine — to-thread / to-subagent

Liveness before success settled

The open to-thread defects (#200, #204, #206) share one class: accepted-then-failed — the spawn reports success, the thread is not alive or attendable. In the pull model there is no babysitter to notice, so this becomes a contract requirement: a dispatch is done when the child is observably alive, not when the command exits. Same principle one layer down is #192: to-subagent validates the promised deliverable before accepting a successful exit.

  • Caller-supplied model/effort settled — to-thread accepts an explicit model; backlog build resolves staffing per ticket and passes it (precedent: closed #48).
  • Attendance relaxation settled — attach-ability is for inspection, not attendance; outcome lands in the tracker either way.
  • Claude Desktop path — #204, evidence gathered: claude --bg then claude://resume import. Two-writers caveat: a running build is inspected via CLI attach; sidebar import is for stopped threads.
  • #203 is a prerequisite open — build keeps orchestrating stages via to-subagent inside its thread; nested wake routing must be fixed or stages dispatch synchronously (the shape #172 found reliable).

Workstream 5Artifact branches & canonicality

Prototypes, research dossiers, and iterating specs live as HTML files on their own branches, never merged to main — version-controlled while they are useful, gone (a deleted ref) when they are not. The ticket carries a projection plus the commit hash it was rendered from, and links the branch. Old specs rot fast and are already reachable from the tracker; main never has to carry or clean them. This refactor's own spec document is the first field test — it lives on this branch.

The shaping change request deleted

Shape's only repo write was glossary terms and ADRs, and it forced the whole readiness-gate apparatus: branch-delta comparison, the three-case readiness logic, merge-changes as a required sibling, re-presented heads. All of it existed to land vocabulary before the work. The timing problem dissolves instead:

  • Main's context files describe the code that is; artifact branches describe the code that will be. A glossary term for an unbuilt feature does not belong on main — it is aspiration, not description.
  • The spec carries a context delta section: new terms, ADR drafts. Agents and issue/PR bodies use that language immediately — it is available from the ticket and the spec branch, which is all "available before work starts" ever required.
  • The build lands the delta. An unsplit ticket writes it into CONTEXT.md/ADRs in its own PR; a split spec carries it as the root commit of its feature branch, reaching main atomically at the capstone merge (WS8 § Landing shape). Either way the merge is the moment "will be" becomes "is," and a direction abandoned before building leaves nothing on main to clean up.
  • Shape's readiness gate collapses to one thing: the blessed hash. No shaping branch ever merges; a clean removal is the only teardown.

One-work verification scripts open

The same rot, different artifact: e2e scripts written to verify one piece of work are not long-standing behavior tests, but today's rule leaves every check in the tree. Proposed classification at the review/evidence stage, mirroring prototype's "keep the answer, delete the scaffolding": a script either asserts durable behavior — it joins the maintained suite — or it is scaffolding — its run and output are captured in the evidence package, and the script is dropped before merge (recoverable from the evidence attachment). You flagged this as unsure; the classification rule is the proposal on the table.

Mechanics

  • Naming convention open — e.g. artifact/<ticket>-<slug>, so every sweep skips these on purpose (they are permanently-unmerged by intent, deletable when spent). The branch ref is also the retention mechanism against GC.
  • History shape open — orphan branches (no shared history) are worth considering for prototypes: no conflicts, no log pollution.
  • Canonicality ADR open — needs ADR — the current rule says the ticket body is canonical; this proposal inverts it: the branch file is canonical, the ticket holds a projection. Two canonical homes are not acceptable; this is a settled-decision reversal and gets an ADR.
  • Blessed-hash readiness settled — the user's blessing records a commit hash. Any later commit on the spec branch past that hash mechanically invalidates readiness. This absorbs #202 nearly for free.

Workstream 6Environment: the parallel-safety checklist

The three-value parallelism verdict (parallel-safe | serialize-verification | sequential) becomes a binary gate: the repo passes the checklist, or build does not dispatch. Lane locks, stale takeovers, and the serialized exception lane are deleted. Setup's job changes from deriving a mode to certifying a checklist and reporting the punch list of gaps:

  1. Worktrees can be created (the worktree skill works here).
  2. A dev stack comes up per worktree.
  3. Auth works per worktree.
  4. Seed data exists and exercises everything the app offers, including new features.
  • The seed is a maintained artifact settled — a ticket that adds a feature also extends the seed, in scope. A seed that misses a feature is drift.
  • Use ≠ change settled — a genuinely shared resource (e.g. a shared Clerk deployment) serves twenty parallel builds that use it and one at a time that changes it. The rare changer tickets are marked at the tracker (slice differently first; a dependency edge only for true residue). The singleton table's collision-mode column records which relation collides.

Workstream 7Communication standard

Three rules for all user-facing text — interview rounds, groom plans, issue and PR bodies, outcome relays, status reports, evidence summaries:

  1. ASD-STE100 plain language. A guidance line in each skill; never a skill invocation per question.
  2. The project's vocabulary comes from the context files. STE is "a small approved dictionary plus your technical names" — CONTEXT.md is the technical-name dictionary, and domain-modeling already maintains it. The two mechanisms compose with no new machinery.
  3. No opaque numbers. Every ticket or PR reference carries its description; relations are said in words. Already law at groom's gate — promoted to family-wide law, reaching the dispatch declaration, outcome relays, merge reports, and watch relays.

Home settled — a small reference-only sibling skill (working name plain-language): the STE discipline, the CONTEXT.md-as-approved-dictionary rule, and the no-opaque-numbers rule in one file. Every user-facing skill names it with a one-line pointer — a pointer, not a duplicate, so the standard has a single source of truth. No playbook and no setup step: the only repo-specific input (the vocabulary) already lives in CONTEXT.md. Optional sibling with standard degradation: absent it, write plainly and say the standard was not loaded.

Workstream 8to-slices

The confirmation stage already exists (draft → present → approve → publish). The delta is small:

  • Posture settled — present the split as a recommendation to edit, not a questionnaire. Aligns with interview's recommended-answer discipline and groom's plan gate.
  • Justification per slice settled new — every slice carries one or two sentences of rationale (why this boundary, why demoable alone); every edge is justified in words. The densest consumer of the communication standard.
  • Step 6 picks up the spec rename; the draft states which blessed spec hash the slices were cut from.
  • Unchanged: readiness audit, dependency-ordered publish, readback, explicit-call-only.

Landing shape — a to-slices decision settled new

The split also chooses how the slices land, recommended with justification like every other cut:

  • Stacked (the default for split specs) — the spec ticket gets a feature branch off main whose root commit is the context delta (CONTEXT.md terms, ADRs, derived from the blessed spec). Slices branch off it and PR into it, inheriting the language from birth. The spec ticket's own PR is the feature→main merge: one ticket, one PR, now universal — and the capstone coverage check becomes the review of exactly that PR. Main receives the vocabulary atomically, when the whole direction becomes true.
  • Direct — independent slices PR straight to main; the first slice carries the delta and is wired as a blocker of the rest. Keeps tracer-bullet continuous integration where slices genuinely don't interlock.

Costs bound to the stacked shape: integration is deferred (a slice that would invalidate the spec surfaces it at the capstone merge, not on day one); main-drift is resolved by the capstone session merging main into the feature branch before its final PR — mechanical conflicts only, a semantic conflict returns the spec to shaping. The artifact branch stays separate from the feature branch: the spec document never merges; the feature branch carries only code. The ticket links both.

Tracking delivered slices — the delivered role settled new

Without it the stacked shape deadlocks: the open-children rule blocks the spec ticket while any child is open, but children only close at the capstone merge, which needs the spec ticket dispatched. The fix is a third visible child state:

  • Open — not yet delivered; readiness labels say unclaimed vs building.
  • Open + delivered — its PR merged into the feature branch, awaiting promotion. This is the policy's existing deferred-closure hook (the built placeholder), made mandatory for stacked runs. Applied by merge-changes in the same act as the merge it performs — slice merges stay human-authorized like every merge.
  • Closed — promoted to main. Closure is native and atomic: Closes #n fires only on default-branch merges, and the capstone PR targets main — so its body carries one Closes line per slice, and GitHub closes them all at promotion. No manual closes.

The dispatch gate refines: the spec ticket becomes dispatchable when every child is closed or delivered — one sentence in the policy's open-children rule, and the deadlock is gone. Honesty on abandonment falls out free: a spec abandoned before promotion leaves its slices open-with-delivered, which is the truth — the work exists on a branch and never shipped. Cosmetic caveat: GitHub's native sub-issue progress counter counts closures, so it undercounts mid-flight; the delivered label is the live signal, and backlog status reads both.

Workstream 12Setups after the refactor

Most setup work built caches, and the refactor's thesis is runtime checks over recorded state — so setups are cut harder than anything else. The surviving principle: setup writes choices, bindings, and certifications — never caches.

Dies

  • Staffing machine audit: reachability probes, effect classes, overlay + stamp, wake paths, permission envelope, alias map
  • Machine-facts discipline: check-machine-facts.py, overlay markers, stamp checks, build's preflight
  • Usage-surface binding (nothing reads it)
  • Parallelism-verdict derivation, lane-lock config

Survives — three categories

  • Bindings (→ platform.md): tracker, review surface, exercised verbs, close-on-merge, the delivered label and feature-branch conventions. Repo data, not machine state; a verb failing at runtime warns and suggests re-binding.
  • Policy choices (→ backlog-policy.md): role→label mapping, creating missing labels (a real tracker write), the spec rename, work domain, readiness autonomy. Human decisions.
  • Certification (→ environment.md): walk the parallel-safety checklist, report pass or punch list. Repeatable on demand; upkeep rides builds.

staffing setup shrinks to a template fill: initial roster from the seed plus a repo-deltas interview — no probes, barely a verb. retro setup keeps its human kernel: recording upstream-feedback consent and creating the tracked ledger. The installer's setup_report stays relevant — fewer setups, each smaller and faster.
