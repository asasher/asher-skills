Getting a repo ready the parallel-safety checklist — the adoption gate

The standard lives in the agent-ready-codebase reference skill; the repo's answers and punch list live in docs/agents/environment.md. backlog setup certifies against the standard — pass, or a punch list of gaps, gaps groomable as tickets — and backlog build dispatches only on a full pass. No modes, no lanes: parallel-safe or not ready.

  1. Worktrees — the worktree skill can create, inspect, and remove working copies here.
  2. Stack per worktree — each working copy brings up its own dev stack beside the others.
  3. Auth per worktree — an agent can mint a session in each copy independently.
  4. Seed — seed data exists and exercises everything the app offers, including new features. The seed is a maintained artifact: a ticket that adds a feature extends the seed in scope; a seed that misses a feature is drift.

Genuinely shared resources (one Clerk deployment, one staging target): use ≠ change. Twenty parallel builds may use it; a ticket that changes it is marked at the tracker (slice first; a dependency edge only for true residue). Parallel-safety is upkeep, not a one-time audit — re-certify on demand.
