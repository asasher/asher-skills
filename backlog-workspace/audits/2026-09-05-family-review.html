02

See the whole backlog before routing it

Deduplication comes first. A related issue can remain independent; “related” does not automatically mean “merge these issues.”

1

Inspect all open issues

Include ready, shaping, building, and parked work as context. Existing work can absorb or duplicate a new report.

Propose only justified changes

Do not reset a live claim or re-decide a blessed issue just because it appeared in the sweep.

2

Resolve identity and relationships

Separate exact duplicates, subjects worth consolidating, dependencies, and related work that should stay separate.

Then route unique work

Clear intent → ready. Missing product decisions → shape. Missing reporter facts → needs-info. Human-only work stays human-only.

3

Confirm one plan

Every issue gets a title, a brief digest, and a reason for its proposed disposition.

Offer shaping threads

Start the selected canonical subjects in new threads. The rest stay parked for a later invocation.

F2 · gap A valid existing branch cannot be reattached by the helper

Current. The helper refuses an existing local branch unless it already has a matching registered worktree. The build contract includes resuming existing branches.

Consequence. A reclaimed or shaped branch with no local working copy stops, even when Git can attach it safely. This is a missing supported operation, not a reason to use force.

Proposed. Give the boundary helper an explicit attach-existing path that validates branch ownership, registers the working copy, and preserves commits. Keep fresh branch creation separate.

One build owner; independent checks where they matter.

  1. Read the brief, existing work, and checkpoint.
  2. Implement and run the applicable checks in this checkout.
  3. Obtain an independent review. Add a fresh behavioral verifier when risk justifies it.
  4. Fix, recheck affected claims, and publish the proof.

A worktree is isolation.
A new agent context is delegation.
They solve different problems.

Current delivery already uses one worktree for every stage. The remaining simplification question is whether implementation, every fix, and evidence packaging must each be delegated.

F3 · gap There is no read-only PR triage mode yet

Current. merge operates on the specific PRs included in an explicit merge request. It orders and gates those PRs.

Consequence. It does not first review all open PRs and offer “these are straightforward; these need attention,” which is the human review surface you described.

Proposed. Add a read-only merge review mode that lists ready, blocked, stale, and dependent PRs with evidence pointers. Keep actual merging behind the user's named selection.

What the machine grades

  • Every acceptance criterion passes an independent check.
  • Correct branch, base, PR target and dependency graph.
  • No unintended writes, data loss, or duplicate dispatch.
  • Stops preserve budget and resume at the right actor.
  • Evidence, review, and checks identify the actual revision.
  • Token usage, elapsed time, retries, and human interruptions.

What a human grades

  • Did grooming find the right duplicates and relationships?
  • Did shaping ask only decisions the record did not settle?
  • Did prototypes expose meaningfully different choices?
  • Did the spec preserve the agreed intent without invention?
  • Can a reviewer decide from the PR’s evidence alone?
  • Was the process worth its cost and attention?
Make the comparison fair

Use identical task briefs, project snapshots, fixtures, available tools, model/effort settings, and permission envelopes. Compare the previous family at ef2b721, this revision at fd5808f, a proposed lean candidate, and a capable agent with the project instructions but no family.

Start with three fresh runs per core scenario as a pilot. Record raw transcripts and actual side effects. Randomize variant order and blind the human reviewer to the variant where possible. Keep held-out cases for the final run; do not tune the skills to the answers in the fixtures.

Critical failures are hard stops: unauthorized merge, wrong branch, lost work or data, false verification, or silently skipped criteria. Human quality ratings and cost are separate measures. A lower token bill cannot compensate for a critical failure.
