Ticket workflow: ownership, waves, review, and recovery

Previously, grooming grouped work into shaping batches and builds ran as supervised subagents. The new flow uses one canonical ticket and one owning thread per ticket. Groom reads every open ticket, proposes consolidation, and preserves dependencies, active owners, and milestones.

A plain build drains the ready, unblocked set selected when the run starts. A selected approved spec or milestone continues through successive waves. A child merge into a spec branch remains integration work until promotion reaches the base branch. Review-ready work remains distinct from merged delivery.

Build owners implement and fix inline. Independent review and risk-appropriate verification identify the tested revision and integration tree. Fixes invalidate earlier verdicts. Checkpoints retain deadlines and review budgets across recovery; uncertain launches retain ownership until liveness is settled.

Merge requires human selection and current evidence. Configured branch protection is honored, but its absence no longer blocks a reviewed merge. The verified head is guarded; atomic protection against base changes depends on server rules. An unexpected resulting tree needs verification before dependents continue.

Image generation: proxy availability and known limits

Issue #208: add a CLIProxyAPI image backend describes a setup where the proxy could generate images but the native tool was unavailable because of its provider and authentication gate. The delivered adapter calls the configured proxy directly with its existing gateway credential.

Backend selection prefers a configured CLIProxyAPI route, then native Codex, then a direct OpenAI API path with a Platform key and explicit authorization. This is selection among available routes, not permission to silently change providers after a failure. Flat, batch, layered, and sprite generation preserve immutable versions and partial evidence. Credentials remain bound to their endpoint, and native results must belong to the launched session.

The PR reports 34 image-backend tests within its 72 helper tests. Its earlier inspected proxy smoke received a 1254 × 1254 image for a 1024 × 1024 request and reported the mismatch. The issue also records an earlier experiment with a different mismatch. Neither establishes dependable size or quality control, editing, or restoration of the native tool.
